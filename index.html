PillClock makes it easier to keep track of the medicines and supplements you plan to take. Add each item with its name, dosage, date, and time, then review your plans in one simple, chronologically organized schedule. Your entries stay saved in this browser, and you can download a CSV copy to keep or print. PillClock is a planning tool only: it does not send reminders or replace medical advice. Follow the directions of your healthcare professional.

PillClock — Product Requirements

A simple, browser-based medicine scheduling companion.

1. Product overview

PillClock helps people organize medicine details and planned times in one calm, readable daily schedule. Users can add a medicine name, dosage, date, and time; review upcoming entries; remove entries; and export the schedule as a CSV file. The app is a lightweight reminder-planning tool, not a medical service.

2. Problem and opportunity

Keeping track of medicine names, doses, and planned times can be difficult when details are scattered. PillClock offers a straightforward place to record and review that information without requiring an account or a complicated setup.

3. Intended users

People who want a simple personal schedule for medicines or supplements, including users who prefer a quick browser-based tool and a downloadable copy of their plan.

4. Product goals

  • Make it quick to add and review a planned medicine entry.
  • Keep the schedule clear, chronological, and easy to manage.
  • Preserve saved entries in the current browser and allow CSV export.
  • Set clear expectations that the app does not provide medical advice or notifications.

5. Functional requirements

  • Capture a required medicine name, dosage, time, and date; reject past dates.
  • Show entries ordered by date and time, with an empty state when none are saved.
  • Allow a user to remove an entry and see the updated reminder count.
  • Persist the schedule in browser local storage and report storage read or save failures.
  • Export saved entries as a CSV file; disable export when the schedule is empty.
  • Display the current date and provide a responsive interface for mobile and desktop.

6. Quality and privacy requirements

  • Use semantic, keyboard-accessible controls and clear labels.
  • Adapt the layout to small screens and respect reduced-motion preferences.
  • Keep schedule data in the user's browser; no account or server sync is provided.

7. Scope boundaries

Automatic alarms, push notifications, medication interactions, dose recommendations, caregiver sharing, cloud backup, and medical record integrations are not part of the current app. Users should follow their healthcare professional’s instructions.

8. Success measures

Users can create, find, remove, and export schedule entries without confusion; saved entries remain available in the same browser; and the interface remains usable across supported screen sizes.

1. Technical overview

PillClock is a client-side web application delivered as a single HTML document. It uses native browser APIs and inline CSS and JavaScript to create, display, store, remove, and export a personal medicine schedule. No application server, user account, or external runtime dependency is required.

2. Runtime and architecture

  • Use semantic HTML for the application, reminder form, schedule, and documentation dialog.
  • Keep presentation in the document's stylesheet and app behavior in its JavaScript closure.
  • Use browser-native form controls, the HTML dialog, localStorage, Blob, and object URLs.
  • Support opening the standalone HTML file in a modern browser without a build step.

3. Reminder data and persistence

  • Store a JSON array under the localStorage key pillclock-reminders-v1.
  • Each reminder contains a string id, name, dosage, ISO date, and 24-hour time.
  • Validate the stored value's array shape and required string fields when loading.
  • Keep data local to the current browser profile; no sync or server backup is provided.

4. Functional and data-flow requirements

  • Require medicine name (up to 70 characters), dosage (up to 40), time, and date; trim text and reject dates before today in local time.
  • Sort schedule items by date and time, render user-provided text as escaped HTML, and allow individual removal.
  • Persist successful additions and removals; if saving fails, retain the previous in-memory list and show an error.
  • Export saved items as UTF-8 CSV with a byte-order mark, quoted fields, escaped quotation marks, and a date-stamped filename.
  • Keep date defaults and comparisons based on local calendar dates rather than UTC date boundaries.

5. Security and privacy

  • Do not transmit schedule data; all persistence is browser-local.
  • Escape user-entered values before inserting them into generated schedule markup.
  • Do not represent the planner as a medical-advice service or an actual alerting system.

6. Accessibility and responsive behavior

  • Use labeled inputs, button controls, live status updates, and accessible names for icon-only actions.
  • Use a modal dialog with a close control, backdrop dismissal, and Escape-key dismissal.
  • Expose the documentation selector as keyboard-operable tabs with selected state and linked panels.
  • Support narrow viewports and reduced-motion preferences.

7. Error handling and verification

Report localStorage read and write failures in the form status area and do not claim a failed change was saved. Verify adding, sorting, reloading, removing, CSV export, empty states, invalid and past dates, documentation navigation and dismissal, keyboard operation, and mobile layouts.
